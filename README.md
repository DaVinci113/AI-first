# Отчёт по авансам: сколько выплачено по каждой работе и договору

Программа на Python (3.11+, без внешних зависимостей) читает выгрузку из `data/`
и строит отчёт на любую дату:

- по каждой работе: цена, выплачено, осталось оплатить;
- по каждому договору: итоги;
- отдельно видно, сколько выплачено «сверх работ» (деньги, которые не удалось
  отнести ни к одной работе отчёта).

## Быстрый старт

```bash
cd candidate-B-solution
python -m contract_report --data data --date 2026-11-10
```

Отчёт печатается в консоль и сохраняется в `out/report_2026-11-10.csv`
и `out/report_2026-11-10.txt`.

Результат на данных из `data/` на 10.11.2026: [out/report_2026-11-10.csv](out/report_2026-11-10.csv).

## Аргументы CLI

| Аргумент | По умолчанию | Смысл |
|---|---|---|
| `--data` | `data` | папка с `contracts.csv`, `works.csv`, `payments.csv` |
| `--date` | обязательный | дата отчёта, `YYYY-MM-DD` |
| `--out` | `out` | куда сохранить CSV и TXT |
| `--no-console` | выкл | не печатать отчёт в консоль |
| `--version` | — | версия |

Пример: `python -m contract_report --data data --date 2026-11-30 --out out`.

При ошибке в данных (битая дата, неизвестный статус, платёж ссылается на
работу другого договора) программа печатает `Ошибка данных: <файл>, строка N: …`
и завершается с кодом 2 — тихо неверного отчёта не будет.

## Отчёт на 10.11.2026 (сводка)

| Договор | Сумма | Выплачено | Осталось |
|---|---|---|---|
| D-1 Студия «Свет» | 600 000.00 | 315 000.00 | 285 000.00 |
| D-2 Иван Петров | 90 000.00 | 75 000.00 | 15 000.00 |

Ключевые детали расчёта (полный разбор — в `DECISIONS.md`):

- возвращённый аванс 50 000 (P-2) не считается выплаченным — деньги вернулись 10.09;
- платёж в очереди 150 000 (P-4) не считается выплаченным — деньги ещё не ушли;
- платёж 20 000 (P-8) от 12.11 не входит в отчёт на 10.11;
- работа W-23 «Упаковка» на 10.11 ещё не принята (принята 11.11) — в отчёте
  она `planned`, но остаток денег по договору (25 000) уже числится за ней;
- работа W-13 «Съёмка: аксессуары» отменена 12.10 — в отчёт на 10.11 не входит.

## Как устроен код

```
contract_report/
  models.py    # доменные модели: Contract, Work, Payment; правила «деньги на дату»
  io_csv.py    # чтение CSV с валидацией форматов и ссылок
  report.py    # расчёт: привязанные и непривязанные платежи, распределение, итоги
  render.py    # вывод: CSV и консольная таблица из одних и тех же строк
  cli.py       # argparse-обёртка, коды возврата 0/2
tests/         # 37 тестов: доменные правила, распределение, валидация, CLI
data/          # исходная выгрузка (не менялась)
```

Принципы: деньги только `Decimal` (никаких float), даты `datetime.date`,
модели неизменяемые (`frozen dataclass`), расчёт отделён от ввода-вывода,
ошибки данных — с именем файла и номером строки.

## Тесты

```bash
python -m pytest tests/ -q
```

37 тестов: правила «деньги на дату» (paid/queued/refunded, возврат после
даты отчёта), распределение непривязанных платежей (done раньше planned,
переплата за работу, отменённые работы), статусы работ на дату, валидация
CSV, интеграционные проверки на данных из `data/` с контрольными цифрами,
CLI (успех, код 2 при ошибке данных).
